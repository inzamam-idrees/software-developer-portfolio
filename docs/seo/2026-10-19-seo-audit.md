## Critical (branch, before or at deploy)

### C1. Set `SITE_URL` at deploy
- Without it, `lib/site-origin.mjs` returns `null`. Canonical tags, sitemap entries, the `robots.txt` sitemap line, `og:image`, `twitter:image` and the JSON-LD `url` are all omitted. That would throw away most of the gains above.
- **Fix:** in Netlify env, set `SITE_URL=https://inzamam-idrees.netlify.app` (exact origin, no trailing path).
- **Failure check:** after deploy, `curl -s https://inzamam-idrees.netlify.app/sitemap.xml` lists 3 absolute URLs, and the home `<head>` has `rel="canonical"` and `og:image`.
- **Next:** verify the site in Google Search Console and Bing Webmaster Tools, then submit the sitemap.
- **Leading indicator:** Search Console "Pages → Indexed" rises to 3.

### C2. No custom domain (strategic)
- A `*.netlify.app` subdomain carries no brand equity. The old `inzamamidrees.netlify.app` URL is already dead, so any links to it are lost.
- **Fix:** register a domain (for example a name-based `.com` or `.dev`), set it as primary in Netlify, 301-redirect the `netlify.app` host to it, set `SITE_URL` to it, and update profile links (GitHub, LinkedIn, dev.to, Stack Overflow, README).
- **Failure check:** `curl -sI https://inzamam-idrees.netlify.app/` returns `301` to the custom domain.

## High

### H1. Same meta description and OG/Twitter text on every page
- `/project` and `/blog` reuse the homepage `description`, `og:title`, `og:description` and `twitter:*` (`app/layout.js` sets them; the route `generateMetadata` only overrides `title`).
- **Fix:** add per-route `description` and `openGraph`/`twitter` titles, as copy keys in `portfolio-data/settings/` (wording is data per CLAUDE.md). Examples: "Selected projects by Inzamam Idrees: Angular, React, Node.js and .NET systems…"; "Articles by Inzamam Idrees on…".
- **Failure check:** the three pages have three distinct `<meta name="description">` values.

### H2. `og:url` missing; `og:locale` invalid
- No `og:url` on any page. `og:locale` is `en`; Open Graph expects `language_TERRITORY` (`en_US`). The code does `locale.replace("-", "_")`, but `site.json` has `"locale": "en"`.
- **Fix:** set `openGraph.url` per route from `canonicalMetadata`, and store the OG locale as `en_US` (or derive it).

### H3. Structured data is minimal
Current JSON-LD (home only):
```json
{"@type":"Person","name":"INZAMAM IDREES","jobTitle":"Senior Full Stack Engineer","address":"Lahore, Punjab, Pakistan","sameAs":[…7 profiles],"url":"…"}
```
Issues:
- `name` is all caps, which comes from `profile.json`. Search engines show it verbatim in knowledge panels.
- `address` is a plain string. It should be a `PostalAddress` (`addressLocality`, `addressRegion`, `addressCountry`).
- Missing `image`, `description`, `knowsAbout` (skills), `worksFor` (current employer from `experience.json`), `alumniOf` (from `education.json`), `email` (if public).
- No `ProfilePage` wrapper. Google documents `ProfilePage` + `mainEntity: Person` for profile pages.
- No `WebSite` node (`name`, `url`).
- `/project` and `/blog` have no structured data. Use `CollectionPage` + `ItemList` of `CreativeWork`/`SoftwareApplication` for projects, and `Blog`/`ItemList` with `BlogPosting` items for articles.
- **Fix:** extend `themes/shared/person-json-ld.jsx` into a shared `@graph` (WebSite + ProfilePage + Person) built only from canonical data. Add route-level JSON-LD for projects and blog. Check each theme renders it, not only Coding.
- **Failure check:** Google Rich Results Test / Schema Markup Validator shows zero errors and detects `ProfilePage`.

### H4. HTML is never cacheable
- `app/layout.js` sets `export const dynamic = "force-dynamic"`. Every page responds `Cache-Control: private, no-cache, no-store`. On Netlify each crawl and visit invokes a server function, so cold starts raise TTFB and LCP. Locally TTFB was 40 ms; production will be slower (not measured).
- This is a regression from the live site: the old build is prerendered and served from Netlify's edge cache (`cache-status: "Next.js"; hit`, `x-nextjs-prerender: 1`). Its 740 ms TTFB is still slow, and the branch could be slower on cold starts.
- Content only changes on redeploy (GitHub store) or admin activation, so the public routes could be static or ISR with on-demand revalidation (activation already revalidates).
- **Fix (needs design, touches theme selection):** render public routes statically or with `revalidate`, and keep preview/admin dynamic. This is an architecture change, so plan it as its own phase.
- **Failure check:** production `curl -sI /` shows a cacheable header (`s-maxage`/`x-nextjs-cache: HIT`) and TTFB under 200 ms.

### H5. Weak, unclear H1s
- Home: `Hello, This is INZAMAM IDREES, I'm a Professional Senior Full Stack Engineer.` The name is in caps, and the sentence is wordy.
- `/project`: `All Projects`. `/blog`: `All Blog` (ungrammatical, no keyword).
- **Fix (copy data):** for example "Inzamam Idrees — Senior Full Stack Engineer (React, Angular, Node.js, Python)", "Projects by Inzamam Idrees", "Articles by Inzamam Idrees". Store the profile name in normal case and uppercase it in CSS where the design wants caps.

### H6. Junk public endpoint `/api/data`
- `GET /api/data` returns `200` `{"success":true,"message":"hle!","data":{"message":"Message and email sent successfully!"}}` (`app/api/data/route.js`). It looks like template leftover. It is crawlable and misleading.
- **Fix:** delete the route if nothing uses it (confirm with grep first). Also consider `Disallow: /api/` and `Disallow: /admin/` in `app/robots.js`. The admin pages already send `noindex`, so robots rules are hygiene only.

## Medium

### M1. No individual project or article URLs
- All 9 projects render on one `/project` page. Long-tail queries such as "Remmi CRM developer" or "Angular POS online ordering" have no dedicated landing page.
- The only blog post links out to dev.to, so all blog equity goes to dev.to and `/blog` is thin (89 words).
- **Fix:** add `/project/[id]` detail pages with unique titles, descriptions, problem/solution/outcome and `CreativeWork` schema. Add them to the sitemap. Optionally mirror articles on-site with `rel=canonical` pointing at whichever copy you choose as primary. This is a new route in every theme, so it needs its own phase.

### M2. No measurable outcomes in projects
- Every project `outcome` is qualitative (for example "A connected view of stock, inventory…"). No project has an image.
- E-E-A-T and recruiter scanning both reward evidence. Add real metrics where you have them (users, latency, revenue, team size). Per CLAUDE.md rule 4, do not invent them; use `[TODO: metric]` until known. Add screenshots with descriptive alt text.

### M3. Sitemap lacks `lastmod`
- `app/sitemap.js` emits `<loc>` only. Add `lastModified` (for example the build time or the content file's git date), and project detail URLs once M1 exists.

### M4. Profile image lazy-loaded
- `<img alt="INZAMAM IDREES" loading="lazy" … inzamam_profile.jpg>`. If it is visible in the first viewport on any breakpoint, use `priority` on `next/image`. Also improve the alt text, for example "Portrait of Inzamam Idrees".
- Decorative SVGs use `alt=""`, which is correct.

### M5. Third-party tag weight
- GTM (`GTM-KHGDRMLM`) plus gtag (`G-NPNZ3HD7P1`) load about 297 KiB, of which Lighthouse marks about 133 KiB unused. TTI is 4.9 s on mobile lab.
- **Fix:** load GA directly via GTM only (not both), or defer it with `@next/third-parties` strategy / consent gating.

### M6. All theme CSS loads on every page
- The root `app/layout.js` imports `portfolio.scss`, `executive.scss`, `admin.scss` and `coding.scss` globally. Lighthouse reports 79% of one stylesheet unused (14 KiB).
- **Fix:** import each theme's styles from its shell, as Spatial already does.

### M7. Social links lack accessible names
- Lighthouse `link-name` fails. The contact section's social icon links (`div.coding-social-links > a`) have no text or `aria-label`, and the inline SVGs carry an empty `<title></title>`.
- **Fix:** add `aria-label` from copy data (for example "GitHub profile"). This affects accessibility and how agents read the page.

### M8. AI search / GEO readiness
- No `/llms.txt`. It is optional and Google ignores it, but some AI tools read it. A short Markdown file with your name, role, skills, projects and contact links is cheap to add.
- The blog content is off-site, and the entity data is thin (see H3). AI answers about "Inzamam Idrees" will lean on LinkedIn and GitHub instead of this site.
- `robots.txt` allows all crawlers, which is fine for visibility. Decide deliberately about GPTBot, ClaudeBot and similar crawlers.

## Low

- **L1. Favicon:** only a 16×16 `favicon.ico`. Add `app/icon.png` (512) and `app/apple-icon.png`; optionally a web manifest.
- **L2. `target="_blank"` links** (5 on home) have no `rel="noopener noreferrer"`. Modern browsers imply noopener, so this is hygiene.
- **L3. `keywords` meta is empty.** Search engines ignore it. Leave it or remove the field.
- **L4. Copy nits:** "1 years ago" on the blog card needs pluralisation; the home H2 reads "Blogs".
- **L5. 404 page** correctly sends `noindex` and links home. Good.
- **L6. Admin/preview:** `/admin/login` sends `noindex, nofollow`; `/preview/*` redirects anonymous visitors to login, and preview is always noindex. Good, and no leak to search engines.
